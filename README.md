# javachannel.org

The website of [#java on Libera.Chat](https://libera.chat/), built with [Quarkus Roq](https://iamroq.com) and
deployed to Cloudflare Pages (project `javachannel-org`) by `.github/workflows/pages.yml`. Pull requests get a
preview deployment.

## Writing a post

Add `content/posts/YYYY-MM-DD-<slug>.md` (or `.html`); it is published at `/posts/<slug>/`:

```markdown
---
title: My post
date: 2026-10-21 12:00:00 +0000
author: yawkat
categories: [java-coding]
tags: [java-25, records]
---

Text in Markdown.
```

- `author` is a key in `data/authors.yml`. Add yourself there; your post list appears at `/author/<key>/`.
- `categories` are keys in `data/categories.yml`. A new category also needs a page in `content/category/`.
- Template syntax is Qute with `quarkus.qute.alt-expr-syntax`: only `{=…}`, `{#…}`, `{/…}`, `{!…}` are special.
  Plain curly braces in code are fine.

## Building locally

```bash
./mvnw quarkus:dev
```

serves the site with live reload on http://localhost:8080. The static site is generated by

```bash
QUARKUS_ROQ_GENERATOR_BATCH=true ./mvnw package quarkus:run
```

into `target/roq`. CI then adds `pages/_redirects.generated` + `pages/_redirects` and `pages/_headers` (Roq skips
files starting with `_`) and runs `migration/verify.py`.

## The WordPress migration

The site was a WordPress blog until 2026. `migration/` holds the one-off conversion; you won't need it for new
content. It is kept so the conversion can be reproduced and checked.

- `export.sh` exports the published posts, pages, terms, authors and approved comments from the WordPress database as
  JSON lines (`wp-export/`), plus the uploads. It is read-only.
- `convert.py` writes `content/posts`, the pages, `content/category`, `content/author`, `data/*.yml`, the uploads in
  `public/wp-content/uploads` and `media/`, and `pages/_redirects.generated`. Post bodies go through WordPress' own
  display filters (`autop.php`: `wpautop`, `wptexturize`, …). These run from a clean WordPress distribution, never
  from the old installation:

  ```bash
  PHP=$(nix build --no-link --print-out-paths nixpkgs#php)/bin/php \
  WORDPRESS=$(nix build --no-link --print-out-paths nixpkgs#wordpress)/share/wordpress \
  python3 migration/convert.py
  ```

  It records the files it writes in `migration/generated.json`. A re-run replaces only those files, so content
  added later is left alone. It refuses to run if one of its files was edited since; `--force` discards such edits.
- `verify.py` checks that every published post and page exists at its WordPress URL with its title, author and date.
  It also checks that internal links resolve, and that no file exceeds the Pages limit of 25 MiB.

Kept from WordPress:
- URLs: posts at `/posts/<slug>/`, pages at `/<slug>/`, `/category/<slug>/`, `/author/<name>/` and `/page/<n>/`.
  Old slugs redirect.
- Redirects to the new locations: `/tag/<slug>/` goes to `/posts/tag/<slug>/`, and `/feed/` to `/rss.xml`.
- `/?p=<id>` links resolve through a script on the home page.
- The RSS feed keeps the WordPress GUIDs, so feed readers don't list old posts again.

Podcast MP3s over 25 MiB are in `media/` and redirect to `raw.githubusercontent.com`. The WordPress "Sample Page" and
all unpublished drafts were not migrated. Comments are closed; the six real comments are shown read-only under their
posts.
